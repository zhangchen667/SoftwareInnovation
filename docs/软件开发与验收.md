# 软件开发与验收

本页把比赛要求和团队目标落实为开发产物、接口交接和验收证据。草版需求见 [F01—F05](需求分析与草版范围.md#2-草版目标与需求)，迭代日期见 [四人分工与排期](分工与排期.md)。文件归属见 [仓库结构](仓库结构与分批提交.md)，正式提交以 [参赛依据及通知](参赛依据.md) 为准。本页用例均为待执行计划，仓库目前有立项文档、纹理基线描述和合成记录示例。

|---|---|---|---|

| R02 · Alpha 工程目标 | 交付可安装 APK，让用户打开并旋转整排模型，再从记录列表打开同一模型 | 另一位队友在 Android 真机从安装开始走 T01。记录 APK 版本、机型和演示数据来源 | C / B |

## 2. 先把接口约定到可以并行开发

Alpha 从 APK 读取配套的合成记录和模型。接入实际计算后，调用顺序是 **Android 界面 → 应用服务 → 算法程序 → 模型结果 → 界面**。两轮先约定共用的模型和记录语义，再根据实施确认服务字段及状态。

| 接口边界 | 双方先约定什么 | 用什么交接 | 谁核对 |
|---|---|---|---|
| 产品 → 客户端 | 启动和记录流程、加载中的操作、成功与失败界面、再次打开记录应回到什么位置 | 界面流程和一个成功、一个失败的操作示例 | B 提供，C 实现并复述 |
| 服务端 → 客户端 | 记录与任务如何关联。提交、查询、完成、失败分别返回什么。失败后怎么重试，演示数据怎么标记 | 一组可解析的合成请求与响应。字段确认前参考已有[合成随访记录](../examples/visit.synthetic.json)，它是记录示例 | D 提供，C 用样例跑界面 |
| 算法 → 服务端和客户端 | 现有程序所需输入、运行入口、成功产物和失败条件。模型格式、牙号、坐标、单位、材质、覆盖标记如何读取 | 一份可分发合成牙列或生成说明，一个结果说明。注明 [P2D](../algorithms/texture/README.md) 对照如何复查 | A 提供模型，D 核对运行和存取，C 核对显示 |

每次交接至少能回答数据从哪来、怎样判断成功、失败后返回什么。出现字段、单位、牙号或错误语义变化，改动方更新同一个接口说明和样例，请下游重跑相关用例。涉及任务状态和数据来源时，先区分模拟任务、已有产物与本次实时计算。首次实现前再按实际框架补精确路径、命令和字段，避免文档里承诺无法调用的接口。

## 3. 开发与复核顺序

| 阶段 | 当阶段要留下的产物 | 阶段结束条件 |
|---|---|---|
| 需求与设计 | 一条用户主流程、适用题面、拟交付范围、界面原型及最小接口 | 四个角色知道自己向谁交付什么，关键数据已有可分享样例或已记录缺口 |
| 分模块开发 | A 交模型及对照，C 交界面与构建方法，D 交接口及运行方式，B 交验收用例与演示路径 | 每块能单独验证，队友能按实际入口运行或打开产物 |
| Alpha 集成 | 可离线使用的 APK、合成模型、正常和错误样例、安装及首次操作说明 | 另一位队友在 Android 真机通过 T01 |
| Beta 集成 | 实际计算入口、服务配置示例、错误处理和可重跑的输入输出记录 | T02、T03、T04 有实测记录。医生端和腕端按实际推进范围记录 T05、T06 |
| 试用与发布 | 修复及复测记录、选定版本、发布包及演示脚本 | 从独立设备和工作目录执行 T07，再生成适用赛段的材料 |

一项任务对应一份可复核的改动。涉及公共配置、模型约定或发布说明时，由目录主责人汇总，消费方复核。新功能的作者负责自测，B 负责汇总独立验收。日常可在本地建短分支和准备差异。更新远端或提交赛事材料遵循根目录 [AGENTS.md](../AGENTS.md) 的授权约定。

## 4. 最小验收用例

| 用例 | 验证动作 | 可观察的预期结果 | 当前结果 |
|---|---|---|---|
| T01 · Alpha 真机（F01—F04） | 从 APK 安装并断开外网，打开合成记录，旋转和缩放，退出后再进入同一记录。另用缺失或损坏的模型样例验证失败提示 | 整排模型及材质可见，记录可重开，入口和详情能看出样例来源。加载失败有返回入口，返回后正常记录仍可打开 | 未执行 |
| T02 · 真实计算 | 提交获准使用的输入，查询状态，打开新结果并核对运行日志 | 任务、记录和模型对应，日志能证明执行了本次计算，完整结果发布后界面才显示完成 | 未执行 |
| T03 · 失败与恢复 | 分别检查缺必要输入、计算失败或断网重连。按实现约定发起重试 | 提示原因和可采取的操作。失败结果未标成功，恢复后能查到对应的任务与记录 | 未执行 |
| T04 · 模型与解释 | 检查整排与重点牙位，比较 P2D 与候选的同视角结果。用遮挡或缺尺度样例检查解释 | 无丢牙或串材质，观测区与估计区区分清楚。不可比处提示原因，未校验尺度时无毫米结论 | 未执行 |
| T05 · 分享权限 | 两名演示医生分别访问同一条记录，患者分享给其中一名，再撤销 | 服务端只允许目标医生在有效授权期内访问或回复。撤销后新请求被拒绝 | 未执行 |
| T06 · 健康闭环 | 在实际可用的穿戴设备与手机上完成记录、选项、反馈及下一次调整 | 能辨认穿戴端的实际作用、数据来源、用户控制项和反馈导致的变化 | 未执行 |
| T07 · 独立复现 | 队友从发布包按说明配置、启动或安装，使用分发样例完成对应版本的演示 | 不需要开发者电脑上的私有路径或账户，显示结果及说明和送测版本对应 | 未执行 |

执行时补一条记录。涉及多个失败分支的用例逐项填写，执行了一项时只报告该项。截图、日志可引用同一份经过检查的证据。

## 5. 从仓库到参赛包

1. **选定版本。** D 记录发布版本和 Git 提交。C 生成该版本 APK，D 写实际环境、配置样例、启动顺序、计算依赖与演示数据说明。README 有可执行入口时补上真实命令和已验证环境。
2. **独立验证。** 非打包成员使用另一台设备和干净目录按说明走一遍，检查软件、界面截图和测试结果对应同一版本。发现遗漏后修正文档或软件，再运行受影响用例。
3. **按赛段导出。** B 对照通知选取计划书、软件、视频或其他材料。开发文档在仓库维护，按要求导出附件或报告。成包前检查匿名信息、模型和素材来源、许可证与文件可读性，剔除私有输入、密钥、缓存及无关历史。正式提交前记录文件清单和已实测功能。
