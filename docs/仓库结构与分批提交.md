# 仓库结构与分批提交

仓库按软件组件组织。[软件交付计划](分工与排期.md) 管角色和排期，[软件开发与验收](软件开发与验收.md) 管接口交接、用例和发布验证。下表包含计划路径，目录与构建入口随对应组件的实际开发创建。

| 路径 | 主责 / 复核 | 存放内容 |
|---|---|---|
| 根目录 | D 维护运行信息 / C、B | README 记录实际环境、入口与状态，AGENTS 统一开发约定。共享构建入口有实际使用时再加 |
| `apps/android/`、`apps/wearable/` | C / B、D | 手机与腕端源码、对应的构建配置、资源和模块测试。若共用 Gradle 工程，腕端可以是 Android 工程中的模块 |
| `apps/doctor-web/` | C，D 协作 / B | 医生网页和前端测试，D 负责服务接入和联调 |
| `services/api/` | D / C、A | 任务、记录、授权及算法调用。依赖与配置示例随服务保存。需要初始化或迁移脚本时随服务版本维护 |
| `algorithms/pose/`、`algorithms/texture/` | A 主做纹理，D 负责运行封装 / C、D | 算法代码、输入输出定义、运行配置、验证和基线说明 |
| `examples/` | 产出方 / 读取方 | 合成模型或生成方法、虚构记录、可公开的接口样例。标明用途及适用接口版本 |
| `docs/` | B 统筹，产出方维护 / 使用方 | 需求、原型、计划、接口、验收与发布说明。证据产生后可按用例编号放入 `docs/evidence/`，仅保留可分发内容 |
| `.local/`、`artifacts/` | 本机 | `.local/` 放私有输入与本机配置，`artifacts/` 放实验结果、构建和导出包。两处均被 Git 忽略 |

## 代码、配置和测试怎样放

- 在各自组件根目录保留实际可运行的构建或启动说明。写明版本、依赖、配置项、首次运行顺序和一条最小验证路径。统一入口按实际集成需要增加，并从根 README 链接。项目的仓库目录和文档可用相对路径。GPU 环境、输入、模型输出等机器相关路径由本地配置传入。
- 用代码所在框架的标准位置存模块测试。跨组件验收先用编号在 [软件开发与验收](软件开发与验收.md) 中记录，形成可复用的集成脚本后随项目维护。验收证据可引用运行记录，保留设备、提交、样例和复测信息。
- 仓库保留能重跑的代码、构建配置及可公开样例。样例模型优先提供合成生成步骤。生成模型、权重、APK、现场视频和最终提交包按选定版本生成或分发。`.gitignore` 对部分模型后缀有忽略规则，新增可公开模型样件时先检查目标路径和授权。
- 共享接口由数据生产方维护并请消费方复核。共改同一份格式说明或配置时，由表中的主责同步实现、样例和用例。文档维护单一开发源，正式附件在选定版本上导出。

## 哪一批放什么

| 提交节点 | 可以提交 | 验收依据 |
|---|---|---|
| 立项与选型（当前） | 计划书、软件规范、模块交接、合成 JSON、P2D 方案标识及来源说明 | 队友能定位当前方案，说清哪些已有、哪些本届开发 |
| 可安装的 Alpha | Android 工程、模型加载、演示服务或内置样例、构建与安装说明 | 能在另一台 Android 设备安装并完成一次查看。牙号和材质对应，演示数据来源可见 |
| 真实计算接入 | 任务封装、可配置路径、状态和接口。按授权迁入所需的既有实现、许可证及版本信息，以独立提交记录本届改动 | 从应用提交到读取结果可以完整操作。用 P2D 核对模型，覆盖任务失败和重试 |
| 可交付的版本 | 对应版本的源码、部署说明、可分发演示样例、测试与发布说明。APK 作为有版本号的构建产物 | 另一名队友按说明构建或安装，能复现演示。记录机型、依赖及软件版本 |

按实际完成时间提交。一次已经完成的历史导入可以放在一个清楚标记的提交里。导入说明记录来源、原作者或项目、形成时间或版本、授权范围、本次改动及验证；形成时间不清楚就写待核实。病例用于本机研究、向队友共享、公开演示与发布到 GitHub 是不同的使用范围。授权记录和原始材料留在受控位置。

## 竞赛仓库和正式提交

通知第 4 页要求本届期间完成作品的核心工作、关键组件和主要开发过程，还要求原创且作品未参加其他国家级公开比赛。Git 记录便于审阅贡献。GitHub 上传时间只表明文件何时进入该仓库。若已有的建模或纹理流程占作品核心，队长应把继承的功能、授权和本届新增工作列清，向组委会询问具体方案是否符合规定，并保留回复。获得使用授权与满足本届原创条件应分别核实。

日常在短分支协作，提交说明和推送授权遵循 [AGENTS.md](../AGENTS.md)。交付比赛时，从确定的版本导出匿名材料，核查说明、截图、文件属性和内嵌路径。初赛与后续阶段的材料区别见 [参赛依据](参赛依据.md)。正式提交入口为赛事官网。[组委会通知正文，第 4–7 页](https://staticfile.eduplus.net/athena/richText/9ed9abcb41cc4cbda5351373a43fa9d1.pdf)
