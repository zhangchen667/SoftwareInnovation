# 牙列纹理

当前展示基线采用 [P2D](baselines/p2d.json)。沿用完整的 14 牙 Mesh 和既有位姿，利用物理表面的邻接关系补色，再对 UV 边界做可微细化。照片支持区域与估计补色区域在交付时应可区分。此处登记的是比赛拟接入的研究基线，仓库目前只有方案描述。

## 本地来源与迁移顺序

在科研工程的 `07_后续实验/mesh_alignment_seam_p1p2_20261117/` 下，`models/p2_surface_refined/` 含 `model.obj`、`material.mtl` 和 14 张逐牙 PNG。它适合先验证读取、牙号与材质匹配。病例衍生的 OBJ 和纹理沿用源数据的授权范围。

要重跑算法，先看同级旧实验 `mesh_alignment_seam_p0_20261117` 的 `experiment.py`、`build_textures.py`、`evaluate_publish.py`，再看本轮 `texture/surface/surface_completion.py` 与 `refine_boundary.py`。后者运行时直接导入 P0 模块。迁入前列出真实输入、缓存来源、第三方依赖与原作者，首个可复现版本应能从声明的输入运行。可先交付读取已有模型的展示能力，再独立验收重新生成纹理的能力。

## 怎样改下一版效果

1. 给新方法起独立名字，例如 `tooth33-seam-v1`。方法有新参数时另建配置，运行输出写入忽略的 `artifacts/<运行名>/`。记录代码提交号、输入版本、参数和相机。
2. 几何和位姿固定时，先用同一相机并排比较 P2D 与候选，再看整排和局部。查相邻牙误采色、可见牙面丢失、实拍区颜色漂移与补色交界。条件允许时补做未参与取色照片的验证，写明条件。
3. 例如 P2I 在 33 号牙跨照片窄缝上试过局部过渡。它能用于回答这一条缝有没有改善；整排采用前，还要核查其他牙和参考视角。裁切或形状变化另做几何对照。
4. 确定替换后新增基线描述，在本页更新默认链接；保留旧描述和相应 Git 提交。安卓与医生端始终按同一模型交接约定读取，算法名只记入结果元数据。

本机已保存 16 个展示资产和 2 个参考脚本的 SHA-256 清单于 `.local/baselines/p2d-20261120.json`。它用于核对比较时是否用了同一批文件。重现计算还需上游输入、依赖和参数。
